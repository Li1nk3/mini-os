## 二、处理机调度

### 2.1 算法实现

实现 4 种典型调度算法:

#### 2.1.1 先来先服务 (FCFS)
按到达时间升序排序,依次执行。若 CPU 空闲且无就绪进程,推进时钟到下一个到达时间。

```c
for (k = 0; k < n; k++) {
    if (t < cur->arrival) t = cur->arrival;
    cur->start = t;
    t += cur->burst;
    cur->finish = t;
}
```

#### 2.1.2 短作业优先 (SJF, 非抢占)
在所有已到达且未完成的进程中,选择 CPU 服务时间最短者执行。

#### 2.1.3 时间片轮转 (RR)
就绪队列采用循环数组实现。每次取出队首执行 `min(quantum, remaining)` 时间;新到达的进程立即入队;若剩余服务时间 > 0,则重新入队。

注意点: 每次推进时钟后立即检查新到达进程并入队,否则可能漏掉刚到达的进程。

#### 2.1.4 优先级调度 (非抢占)
在已到达进程中选择优先级数值最小者(优先级越高数值越小)。

### 2.2 性能指标

对每个进程计算:
- 周转时间 = 完成时间 − 到达时间
- 等待时间 = 周转时间 − 服务时间
- 响应时间 = 首次开始时间 − 到达时间
- 带权周转时间 = 周转时间 / 服务时间

并输出平均值。

### 2.3 实验结果

测试数据(到达时间 / 服务时间 / 优先级):
| PID | 到达 | 服务 | 优先级 |
| --- | --- | --- | --- |
| 1 | 0 | 4 | 3 |
| 2 | 1 | 3 | 1 |
| 3 | 2 | 5 | 4 |
| 4 | 3 | 2 | 2 |

| 算法 | 完成时间 | 平均周转 | 平均等待 | 平均响应 |
| --- | --- | --- | --- | --- |
| FCFS | 14 | 7.75 | 4.25 | 4.25 |
| SJF | 14 | 6.75 | 3.25 | 3.25 |
| RR(q=2) | 14 | 9.25 | 5.75 | 2.00 |
| Priority | 14 | 7.00 | 3.50 | 3.50 |

**分析**: 在本数据集上,SJF 的平均周转时间最优(6.75);RR 因为频繁切换、所有任务都需要等待自己的下一时间片,平均周转/等待最高(9.25 / 5.75),但平均响应时间最优(2.00),说明短作业能更快被服务到。FCFS 实现最简单但对短作业不友好(P4 等待 9 个时间单位)。Priority 在合理设置下接近 SJF,但需依赖外部给出的优先级。

## 三、内存管理

### 3.1 动态分区

**数据结构**: 分区表为有序数组,元素 `(id, start, size, free, pid)`。

**分配策略**:
- First-Fit: 顺序扫描,选第一个能容纳的空闲分区。优点: 速度快;缺点: 低地址易产生碎片。
- Best-Fit: 选最小且能容纳的分区。优点: 大分区被保留;缺点: 易产生大量小不可用碎片。
- Worst-Fit: 选最大分区。优点: 剩余分区大,后续仍可用;缺点: 大分区被破坏。

**释放与合并**: `mem_free` 标记目标分区为空闲后,扫描分区表,把相邻空闲分区合并。

### 3.2 页面置换

- **FIFO**: 用循环指针记录最早装入位置。
- **LRU**: 每帧记录"上次访问的步号",淘汰最小者。
- **OPT**: 对每个帧扫描未来访问序列,淘汰最远才再次访问(或永不访问)的页面。仅作为理论下限对比。

### 3.3 实验结果

经典 Belady 序列 `7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1`,3 个物理块:

| 算法 | 缺页次数 | 缺页率 |
| --- | --- | --- |
| FIFO | 15 | 75.0% |
| LRU | 12 | 60.0% |
| OPT | 9 | 45.0% |

**分析**: OPT 是理论最优,实际系统无法实现;LRU 接近 OPT,是常见实现选择;FIFO 实现简单但在该序列下表现最差,且存在 Belady 异常(增加帧数反而增加缺页)。

## 四、进程同步

### 4.1 生产者-消费者

**临界资源**: 环形缓冲区 `buffer[size]`。
**信号量**:
- `empty` 初值 = size,空槽数
- `full` 初值 = 0,满槽数
- 互斥锁 `mu` 保护 in/out 指针

**生产者**:
```
P(empty); P(mu); buffer[in]=item; in=(in+1)%size; V(mu); V(full);
```
**消费者**:
```
P(full); P(mu); item=buffer[out]; out=(out+1)%size; V(mu); V(empty);
```

正确性: 通过 `empty` 与 `full` 信号量保证不会越界;互斥锁防止多个生产者(或多个消费者)并发修改 in/out。

### 4.2 读者-写者

**写者优先版**: 额外引入 `r_try` 锁,当至少有一个写者等待时,新读者必须先获取 `r_try` 才能进入,而 `r_try` 已被写者持有,从而阻止读者进入,避免写者饥饿。

```c
// 写者
P(wc_mu); writers_waiting++;
if (writers_waiting == 1) P(r_try); V(wc_mu);
P(rw_mu); /* 写 */ V(rw_mu);
P(wc_mu); writers_waiting--;
if (writers_waiting == 0) V(r_try); V(wc_mu);

// 读者
P(r_try); V(r_try);             // 写者优先时阻塞
P(rc_mu); readers++;
if (readers == 1) P(rw_mu); V(rc_mu);
/* 读 */
P(rc_mu); readers--;
if (readers == 0) V(rw_mu); V(rc_mu);
```

### 4.3 哲学家就餐

**策略 1 - 资源分级**: 总是先拿编号小的筷子,后拿编号大的。
正确性证明: 假设存在死锁,则存在循环等待 P0 → P1 → ... → Pk → P0。每条边代表"等待某编号筷子",但每个进程持有的筷子编号都小于其等待的筷子编号(因为先小后大),所以沿循环最终回到自己时编号必须既严格大于又严格小于,矛盾。

**策略 2 - 房间信号量**: 用信号量 `room = n-1` 控制最多 n-1 人同时尝试就餐。无论怎么取,总有人能两根都拿到,因此无死锁。

## 五、文件系统

### 5.1 整体布局

磁盘镜像 `fs.img` 的逻辑布局:
```
| 超级块 SuperBlock | 块位图 Bitmap | inode 表 | 数据块区 |
       1 块            1+ 块         ~7 块     ~1015 块
```

参数:
- 总块数: 1024
- 块大小: 512 B
- 总容量: 512 KB
- inode 数: 128
- 每个 inode 直接指向最多 8 个数据块,单文件容量上限 = 8 × 512 = 4 KB

### 5.2 关键数据结构

```c
typedef struct {
    uint32_t magic;          // 文件系统魔数 'OSFS'
    uint32_t total_blocks;
    uint32_t block_size;
    uint32_t inode_count;
    uint32_t bitmap_block;
    uint32_t inode_block;
    uint32_t data_block;
    uint32_t root_inode;
} SuperBlock;

typedef struct {
    uint32_t type;           // 0=空闲 1=文件 2=目录
    uint32_t size;           // 字节数
    uint32_t blocks[8];      // 直接索引
    uint32_t block_count;
    uint32_t parent;         // 父目录 inode
    char     name[28];
} Inode;
```

目录的数据块中存放 `DirEntry` 数组,每个条目 32 字节,一个 512B 数据块可容纳 16 个目录项。

### 5.3 空闲空间管理

采用**位图法**: 每个块对应 1 bit,1=已分配, 0=空闲。`alloc_block` 顺序扫描位图找到第一个空闲块。

替代方案对比:
| 方法 | 优点 | 缺点 |
| --- | --- | --- |
| 位图 | 紧凑、查找连续块容易 | 块多时位图大 |
| 空闲链表 | 任意大小,无需位图 | 不连续遍历开销大 |

本实现使用位图,在 1024 块下仅需 128 字节(< 1 块)。

### 5.4 支持操作

| 命令 | 功能 |
| --- | --- |
| format | 创建/重置镜像 |
| mount  | 加载镜像 |
| ls     | 列出当前目录 |
| mkdir  | 创建目录 |
| create | 创建空文件 |
| write  | 覆盖写入内容 |
| cat    | 读取并显示文件 |
| rm     | 删除文件/空目录 |
| cd     | 切换目录,支持 `/`、`..` |
| stat   | 镜像使用统计 |
| bitmap | 显示位图 |

### 5.5 持久化

所有元数据(超级块、位图、inode 表)在每次修改后调用 `persist_meta` 写回磁盘并 `fflush`。重新启动后 `mount` 即可恢复完整状态。

## 七、心得与不足

**收获**:
- 通过亲手实现 4 个核心模块,加深了对调度、内存、同步、文件系统的工程化理解。
- 实践 POSIX 线程与信号量,直观体会到死锁、饥饿等并发问题的成因与解决思路。

**不足**:
- 调度仅实现非抢占式版本,未加入 SRTF、多级反馈队列等更复杂的策略。

**后续可拓展**(对应课程"提升部分"):
